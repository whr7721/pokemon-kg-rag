# 宝可梦 GraphRAG 问答系统评测报告（阶段二）

> 评测人：成员三（李宗恒，生成与评测）
> 日期：2026-09-12
> 模型：tju-llm（天津大学大模型平台）
> 向量化：BAAI/bge-m3（SiliconFlow 云端 API，1024 维）
> 图谱：Neo4j Aura（实例 1f1a6400）

---

## 一、评测目的

对比三种问答策略在宝可梦知识问答上的效果差异，验证 GraphRAG（文本块 + 图谱事实注入）相对于普通 RAG（纯文本块检索）和结构化直答的优势，为系统优化和最终汇报提供数据支撑。

---

## 二、评测设置

### 2.1 三种对比策略

| 策略 | 说明 | 实现方式 |
|---|---|---|
| 结构化直答 | 对进化/克制/关系/特性/策略类问题直接查图返回，不经过 LLM | `multi_qa.py` 规则路由 + Cypher 直查 |
| 普通 RAG | 向量检索相关文本块，拼入 Prompt 让 LLM 回答，不注入图谱事实 | `rag.ask(use_graph=False)` |
| GraphRAG | 向量检索文本块 + 从图谱提取命中实体的关系事实，共同拼入 Prompt | `rag.ask(use_graph=True)` |

### 2.2 评测题目设计

共设计 **22 道题**，覆盖 9 个类别：

| 类别 | 题数 | 代表问题 | 考察点 |
|---|---|---|---|
| 实体属性 | 2 | 妙蛙种子的属性是什么？皮卡丘的分类是什么？ | 单实体事实检索 |
| 多跳进化 | 3 | 小火龙的最终进化是谁？妙蛙种子多少级进化成妙蛙草？ | 跨实体多跳关系 |
| 招式筛选 | 3 | 哪些火属性招式威力大于80？威力最高的电属性招式？ | 条件筛选+列表生成 |
| 双属性克制 | 3 | 草+毒属性被什么属性克制？火+飞行抵抗什么？ | 双属性叠加计算 |
| 特性 | 2 | 茂盛特性的效果是什么？猛火特性触发条件？ | 特性精确描述 |
| 蛋群 | 2 | 妙蛙种子属于什么蛋群？哪些同时属于怪兽和龙蛋群？ | 蛋群关系 |
| 图鉴 | 2 | 全国图鉴编号25的宝可梦是谁？喷火龙的图鉴编号？ | 编号反查 |
| 资料不足 | 2 | 阿尔宙斯的属性是什么？超梦的隐藏特性？ | 抗幻觉/边界处理 |
| 比较类 | 3 | 喷火龙和水箭龟谁特攻更高？火系和水系招式平均威力谁高？ | 数值比较（图谱缺种族值） |

题目清单详见 `scripts/run_eval.py` 中的 `QUESTIONS` 列表。

### 2.3 判分方法

采用**确定性判分**（关键词匹配 + 图查询验证），0-5 分制：

| 分数 | 标准 |
|---|---|
| 5 | 完全正确，覆盖全部要点 |
| 4 | 正确，有小瑕疵（遗漏次要信息） |
| 3 | 部分正确，核心要点对但不完整 |
| 2 | 仅少量正确信息，大部分错误 |
| 1 | 错误但无幻觉 |
| 0 | 资料不足（当应有答案时）或严重幻觉 |

对有明确标准答案的题（如属性、进化、编号），额外用 Neo4j 图查询验证标准答案（如 `MATCH (p:Pokemon {name_zh:'喷火龙'}) RETURN p.pokedex_id`）。

判分脚本：`scripts/score_eval.py`，输出 `scripts/eval_scores.json` 和 `scripts/eval_scores.md`。

### 2.4 Prompt 改进

阶段二对 Prompt 进行了针对性改进，针对招式筛选和双属性克制两类弱项：

**改进前**：
```
你是一个宝可梦知识助手。请优先参考上下文中的【图谱结构化事实】和【检索文本块】准确回答问题。
如果上下文完全不足以回答，请直接说"资料不足"。
```

**改进后**：
- 强化身份约束："只根据给定上下文回答，绝不使用外部知识或猜测"
- 增加 5 条回答规则：优先图谱精确数据、列表要列全、双属性分别分析再综合、资料不足直接说
- 增加 3 个 few-shot 示例：招式筛选、双属性克制、资料不足
- 强化防幻觉和资料不足约束

## 三、总体结果

### 3.1 改进后最终结果（Prompt 优化后）

| 策略 | 平均分 | 答对题数（≥4分） | 答对率 |
|---|---|---|---|
| 结构化直答 | 1.41/5 | 6/22 | 27% |
| 普通 RAG | 2.27/5 | 9/22 | 41% |
| **GraphRAG** | **4.36/5** | **19/22** | **86%** |

**GraphRAG 比普通 RAG 高 2.09 分，答对率高出 45 个百分点；比结构化直答高 2.95 分。**

### 3.2 Prompt 改进前后对比

| 策略 | 改进前平均分 | 改进后平均分 | 提升 | 改进前答对 | 改进后答对 |
|---|---|---|---|---|---|
| 普通 RAG | 2.09/5 | 2.27/5 | +0.18 | 9/22 | 9/22 |
| GraphRAG | 3.95/5 | 4.36/5 | **+0.41** | 18/22 | 19/22 |

**Prompt 改进对 GraphRAG 效果更显著**（+0.41 分），因为 GraphRAG 上下文更丰富，few-shot 示例能更好地引导 LLM 利用图谱事实。

## 五、典型案例分析

### 5.1 GraphRAG 完胜案例

**案例 1：多跳进化（q03 小火龙的最终进化是谁？）**
- 结构化直答：✅ 完整进化链（小火龙→火恐龙→喷火龙）
- 普通 RAG：✅ 喷火龙（改进后也能答出）
- GraphRAG：✅ "根据图谱事实，小火龙的最终进化是喷火龙。"
- **分析**：进化链是典型的多跳关系，GraphRAG 通过图谱事实直接拿到完整进化链，答案精确且有依据。

**案例 2：特性精确描述（q12 茂盛特性的效果是什么？）**
- 普通 RAG：⚠️ "HP减少的时候，草属性的招式威力会提高"（模糊描述）
- GraphRAG：✅ "当HP小于1/3时，草属性招式的威力增长为1.5倍；当HP小于1/4时，伤害增长为2倍"（精确数值）
- **分析**：特性的精确触发条件和数值倍率存储在图谱结构化事实中，普通 RAG 只能从文本块拿到模糊描述，GraphRAG 能拿到精确数值。

**案例 3：资料不足处理（q18 阿尔宙斯的属性是什么？）**
- 普通 RAG：❌ "资料不足"（没检索到）
- GraphRAG：✅ "一般"（图谱里有阿尔宙斯的数据）
- **分析**：阿尔宙斯作为传说宝可梦，文本块可能没覆盖，但图谱实体节点里有属性数据，GraphRAG 通过实体事实直接拿到。

### 5.2 弱项案例

**案例 4：比较类问题（q20 喷火龙和水箭龟谁的特攻更高？）**
- 三者均答："资料不足（上下文中没有种族值数据）"
- **分析**：图谱中缺少种族值（特攻/特防/速度等）数据，这是数据层面的缺失，不是检索或 Prompt 能解决的。需要成员一在阶段二补全种族值数据。

**案例 5：图鉴反查（q16 全国图鉴编号25的宝可梦是谁？）**
- 三者均答："资料不足"
- **分析**：向量检索和全文索引都是按"名字"检索，按"编号反查名字"需要反向索引或直接图查询。当前检索策略不支持编号反查，这是检索层面的局限。

## 六、核心发现与结论

### 6.1 核心结论

1. **GraphRAG 显著优于普通 RAG 和结构化直答**：平均分 4.36/5，答对率 86%，分别比普通 RAG 高 2.09 分和 45 个百分点。

2. **图谱事实注入是关键提升因素**：在多跳进化、特性精确描述、蛋群、资料不足等类别上，GraphRAG 完胜普通 RAG，因为这些问题的答案存储在图谱结构化事实中，纯文本块检索无法覆盖。

3. **结构化直答适用范围有限**：只在进化类问题上表现较好（3.67/5），其他类型基本不命中（因为规则路由只覆盖进化/克制/关系/特性/策略），且不经过 LLM 润色，答案格式较生硬。

4. **Prompt 改进有效**：增加 few-shot 示例和回答规则后，GraphRAG 平均分提升 0.41 分，特别是招式筛选和双属性克制两类弱项改善明显。

5. **数据缺失是主要瓶颈**：比较类问题（种族值对比）三者均无法回答，因为图谱中缺少种族值数据；图鉴编号反查也因缺少反向索引而失败。这些是数据和索引层面的问题，需要在后续阶段补全。

### 6.2 GraphRAG 的优势场景

- **多跳关系查询**：进化链、属性克制链等需要跨多个实体的查询
- **精确数值查询**：特性触发条件、招式威力、进化等级等有精确数值的查询
- **文本块未覆盖的实体**：传说宝可梦、冷门招式等文本块可能没覆盖但图谱里有数据的实体
- **资料不足判断**：GraphRAG 能更准确地判断何时该说"资料不足"，减少幻觉

### 6.3 GraphRAG 的局限场景

- **需要数值比较的问题**：种族值对比、平均威力计算等需要跨实体数值聚合的问题
- **按非名字字段反查**：按编号反查名字、按威力反查招式名等需要反向索引的问题
- **图谱数据缺失的领域**：如果图谱里本身没有某类数据，GraphRAG 也无法回答

## 七、局限性与改进方向

### 7.1 当前评测的局限性

1. **题目规模较小**：仅 22 道题，类别覆盖有限，统计显著性有待提升。建议阶段三扩充到 50+ 题。
2. **判分以确定性为主**：主要用关键词匹配和图查询验证，缺少 LLM 语义评分和人工复核。部分主观题（如答案完整性）的判分可能有偏差。
3. **未做消融实验**：未单独测试"仅向量""仅全文""hybrid""hybrid+图谱事实"等不同检索策略的效果差异。建议与成员二配合完成检索消融实验。
4. **本地模型 vs 云端模型差异未完全量化**：评测初期曾用本地 BGE-M3 模型测试，核心结论（GraphRAG 显著优于普通 RAG）一致，但具体数值有细微差异。最终结果以云端 SiliconFlow 模型为准。

### 7.2 后续改进方向

1. **补全图谱数据**：
   - 补全种族值（HP/攻击/防御/特攻/特防/速度），支持比较类问题
   - 补全更多招式的精确威力和命中值
   - 补全图鉴编号反向索引

2. **优化检索策略**：
   - 实现 hybrid retrieval（向量 + 全文索引分数融合）
   - 增加按编号/威力等非名字字段的检索能力
   - 调整 top_k 和融合权重参数

3. **增强 Prompt**：
   - 增加更多类别的 few-shot 示例（比较类、图鉴反查）
   - 优化引用格式，要求答案标注信息来源（图谱事实/文本块）
   - 增加思维链（CoT）引导，特别是双属性计算和列表筛选

4. **扩充评测集**：
   - 扩充到 50+ 题，增加每个类别的题量
   - 增加对抗性问题（诱导幻觉的问题）
   - 增加多轮对话评测
