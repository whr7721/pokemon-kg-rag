# Pokémon Knowledge-Graph RAG System

> Course project for *Knowledge Engineering Practice* — final stage-2 release.
> 1,025 Pokémon · 41,507 embedded text chunks · ~140k graph relationships.

An end-to-end Chinese question answering system built on a **Neo4j knowledge graph** plus
**retrieval-augmented generation**. A deterministic build engine turns the
[pokemon-dataset-zh](https://github.com/42arch/pokemon-dataset-zh) JSON dataset into an enhanced
graph (forms, 18x18 type-effectiveness chart, evolution conditions, hit profiles) and renders
entities and relations into text chunks with 1024-dim embeddings.

Questions are answered by a unified router:

1. **MultiQA strategy** — deterministic Cypher answers for attribute / evolution / ability /
   move / counter / strategy questions, no LLM involved;
2. **GraphRAG strategy** — hybrid retrieval (vector + full-text + RRF), KG²RAG graph expansion along
   type, evolution, ability and egg-group edges, neighbourhood facts injected into the prompt,
   generated by the university Qwen (tju-llm) endpoint with evidence and subgraph returned to the UI.

## Highlights

| Feature | Detail |
| --- | --- |
| Switchable retrieval paths | `vector` / `fulltext` / `hybrid` / `hybrid_graph` selectable in the web UI, with the active path shown on the answer badge and evidence panel |
| KG²RAG expansion | Graph-structural expansion recovers counter/shield questions that pure semantic retrieval misses entirely (4 of 19 questions flipped from miss to hit) |
| Dual-type hit profiles | 1,019 pre-computed damage-taken chunks remove the LLM's mental math on dual-type multipliers |
| Unified routing | MultiQA and GraphRAG became two strategies behind one `RagRouter` sharing a single `GraphAccess` layer |
| Reproducible evaluation | 22-question three-way generation benchmark + 19-question four-way retrieval ablation + parameter grid, all scripted |

## Results

| Strategy | Avg score | Correct (>=4) | Accuracy |
| --- | ---: | ---: | ---: |
| Structured direct answer | 1.41 / 5 | 6 / 22 | 27% |
| Naive RAG (text chunks only) | 2.86 / 5 | 11 / 22 | 50% |
| **GraphRAG (chunks + graph facts)** | **4.05 / 5** | **17 / 22** | **77%** |

| Retrieval path | Hits | Recall |
| --- | ---: | ---: |
| `vector` | 9 / 19 | 47.4% |
| `fulltext` | 3 / 19 | 15.8% |
| `hybrid` | 9 / 19 | 47.4% |
| **`hybrid_graph`** | **14 / 19** | **73.7%** |

## Quick start

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
copy .env.example .env      # fill in Neo4j / embedding / LLM credentials
python src\app.py           # open http://127.0.0.1:5000
```

Full rebuild pipeline (requires a reachable Neo4j instance):

```powershell
python src\build_graph.py --out build_out    # deterministic build artifacts
python scripts\load_engine_out.py --clean    # import entities + entity chunks
python scripts\embed_relation_chunks.py      # embed relation + hit-profile chunks
python scripts\embed_vectors.py              # embed remaining chunks
python scripts\setup_indexes.py              # vector / full-text indexes and constraints
```

See `README.md` (Chinese) for the full architecture, schema statistics, API reference and
evaluation details, and the `docs/` folder for the retrieval, evaluation and progress reports.

## Tech stack

Neo4j AuraDB · neo4j-graphrag-python · BAAI/bge-m3 (1024-d) · tju-llm (Tianjin University) ·
Flask + vis-network · Python 3.14
